# 简版｜个人使用版

根据 `原始逐字稿` 与已经完成的 `【中文可读版】`，生成供科技记者快速阅读、检索、引用和继续写稿的 `【个人使用版】`。这不是只有几条结论的摘要：必须沿着原始时间轴讲清主要内容，并保留报道所需的事实与细节。

## 时间轴与覆盖范围

- 保持原始时间顺序。原稿有时间码时，保留有意义的时间点或连续时间段，例如 `[00:00–06:30]`；不要为每一句都加时间码。
- 原稿没有时间码时不要编造。仍须按原始顺序识别话题转换并主动分段，使用 `第一部分｜话题名称`、`第二部分｜话题名称` 或清楚的话题小标题组织；不能退化成一整块连续文字。
- 必须覆盖整份素材。单人演讲之后的访谈、Q&A、媒体或观众提问都要继续处理。
- 每一个实质话题和重要说话人回合都要有所体现。可以压缩重复铺垫、寒暄和空转，不得只摘取少数亮点。

## 每个时间段应讲什么

- 用简洁、连贯的中文说明这一段的主要内容、问题与回答、判断形成过程和关键结论。
- 优先保留：技术原理与机制、研发策略与取舍、测试方法与可靠性、数字与约束、演示和操作流程、真实场景、团队决策与迭代、制造与供应链、软硬件和 AI 细节、行业比较、比喻和命名概念。
- 保留重要的人名、公司、产品、版本、发布时间、数量、比例、收入、客户、融资和性能指标。
- 不要过度压缩高密度技术段落，不要把具体场景替换成抽象判断。
- 保留能引出信息的主持人问题；合并重复提问和纯社交对话。
- 正文只写说话人实际表达的内容，不把编辑推断混入发言。

## 概览块

只有当连续约 5–10 分钟都围绕同一主题时，才在对应时间段后加入 `（概览/总结）`：

- 概括主持人的核心关切、发言者的方法或策略，以及这一段的主要内容。
- 原文缺少样本量、测试时长、失败率、硬件参数、控制方法或比较基线时，可明确写 `信息缺口：…`。
- 概览只能依据素材，不得补充外部知识或自行下判断。

## 与清洗版的关系

- 以 `【中文可读版】` 为事实底稿；只为恢复时间码、说话人、技术细节、演示动作、数字或被压缩的信息返回检查原始逐字稿。
- 沿用清洗版中的 `[[?不确定片段?]]`，不得自行消除不确定性。
- 内容比清洗版短、更方便阅读，但仍是带时间线和说话人脉络的工作稿，不是营销文案或文章。

建议结构：

【个人使用版】

[00:00–06:30] 话题名称

**主持人：** ……

**嘉宾：** ……

（概览/总结）
这一段主要……

输出严格 JSON，不使用 Markdown 代码围栏：

{"simple":"【个人使用版】\n\n按时间轴整理的主要内容"}
